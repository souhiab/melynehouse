# Customer storefront UX audit and roadmap — 2026-11-01

This audit used the existing Unslop skill by Damir Sokolovsky (CC BY 4.0) in light-polish mode. The design direction is **warm, direct, orderly**: MELYNE's real clothing photographs provide the visual detail; cream space, dark-green controls, Arabic Cairo typography, and the butterfly mark provide continuity. The catalog heading was the only area changed in this phase. Browser evidence is in [qa-catalog-phase1](qa-catalog-phase1/), and measurements are in [catalog-product-first-qa.md](catalog-product-first-qa.md).

## Findings, ranked for future work

| Priority / effort | Page or component | Observed problem and evidence | Customer impact | Recommended next step and expected benefit |
| --- | --- | --- | --- | --- |
| **High / Small** | Public catalog content | A published product title includes `اختبار PostgreSQL محلي` in its breadcrumb/cart and can appear in listings. **Visually verified** on product, cart, and checkout captures. | Test wording can undermine trust and confuse buyers. | Owner should review that product's published name/status in the existing dashboard; keep its history. This is a content decision, so no catalog record was changed in this phase. |
| **High / Medium** | Product detail on phones | The large first image and thumbnail area put price, variants, stock, and actions below the initial 390 px viewport. **Visually verified** in `before-product-390.png`. | Customers must scroll before they can choose a variant or buy. | In a later phase, improve the mobile product-information sequence while keeping gallery quality and the agreed three purchase actions. This should make selection easier to reach. |
| **High / Medium** | Mobile checkout | The form is readable, but confirmation falls below the first viewport after required fields and the summary. **Visually verified** in `before-checkout-390.png`; the prior checkout pass already removed much excess space. | Buyers have a longer path to the final action. | Evaluate a single accessible sticky summary/action or further form density improvements without duplicating submit or covering inputs. Benefit: easier order review and confirmation. |
| **Medium / Medium** | Homepage | The family hero and photographic categories occupy nearly the full first viewport before featured product cards. **Visually verified** at 1440 and 390 px. | Returning shoppers reach actual products later than on a listing. | In a separate homepage phase, test a compact path from hero/categories to featured products while preserving the approved imagery and benefits. |
| **Medium / Small** | Cart | At 390 px, the large title region pushes the item and order summary down; the page is otherwise readable. **Visually verified** in `before-cart-390.png`. | Cart review takes extra scrolling. | Tighten only the cart heading and section spacing in a later phase. Expected benefit: item and total appear sooner. |
| **Medium / Small** | Mobile header and search | The global mobile search is behind an icon and drawer; desktop header occupies about 176 px including announcement and nav, mobile about 103 px. **Visually verified** for height; drawer flow **inferred from `src/App.jsx`**. | Search takes an extra tap on phones; header height contributes to scroll distance. | Review navigation and search discovery as a distinct header phase. Preserve cart, wishlist, contact, and category links. |
| **Medium / Small** | Mobile menu accessibility | `MobilePanel` locks scroll and handles Escape, but its code does not contain an explicit focus trap or focus-return step. **Code-inferred**, not an assistive-technology test. | Keyboard and screen-reader users may lose their place. | Add modal focus management and test with keyboard and a screen reader when the header phase is authorized. |
| **Medium / Small** | Catalog search and filters | The drawer now preserves real size/color labels, some of which are English; the selected product count updates. **Visually and browser verified**. | Mixed-language labels are less quick to scan in an Arabic store. | Review label presentation with the owner; preserve exact option values in data and orders. No invented translations or changed filters. |
| **Low / Medium** | Frontend performance | The production build reports large main/admin JS chunks. **Build verified**; load-time impact was not measured. | Could slow first interaction on weaker devices. | Measure with a local performance trace, then split storefront/admin code if the trace supports it. No speed claim is made here. |

## Phase 1 issue resolved

All Products and category pages used a tall decorative heading area and repeated count information, making the first product image start at 596 px on desktop and 523 px at 390 px. The compact shared heading now starts real products at 348 px and 346 px respectively. It retains the semantic category title, actual count, secondary breadcrumb, search, on-demand filters, sorting, real prices, and product cards. See the QA report for screenshots and validation.

## Boundaries

The roadmap is a recommendation list. Homepage, global header, product detail, cart, checkout, backend, and catalog records were **not** changed for this phase. No conversion-rate or performance gain is claimed without measurement.
